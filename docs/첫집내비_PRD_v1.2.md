## 1. 문제와 성공 기준

첫 독립을 준비하는 청년은 받을 수 있는 주거 지원이 있어도 공고가 기관마다 흩어져 있고 조건이 어려워 놓치기 쉽다. 후보 집을 고를 때도 집의 보증금·월세에 따라 받을 수 있는 지원이 달라진다는 점을 알기 어렵다. 첫집 내비는 대화로 확인한 내 상황을 재사용해, 공고 근거가 있는 지원 추천과 지원까지 반영한 후보 집 비교를 이어서 보여준다.

사용자는 직방·다방 등에서 본 후보 집을 들고 와서 "어디로 갈지" 고른다. 매물은 우리가 가져오지 않고(공개 API 없음, 크롤링 안 함) 사용자가 직접 넣는다.

시연 성공 기준은 다음과 같다.

1. 1단계 대화로 9개 항목을 입력하고 정리 카드에서 수정한다.
2. 2단계에서 받을 수 있는 지원 총액("최대 520만 원"), 정책별 판정 근거와 공고 링크, 지금 신청 가능 / 내년 신청 지원을 확인하고, 공고문에 질문해 근거 있는 답을 받는다.
3. 1단계 조건을 바꾸면 지원 금액이 다시 계산된다 (예: 27세 520만 원 → 35세 280만 원).
4. 3단계에서 후보 집 2~3곳의 한 달 실부담·출퇴근·생활 편의·집별 지원 판정을 한 화면에서 비교한다.
5. 우선순위를 바꾸면 점수와 추천 이유가 갱신된다.

## 2. 사용자 흐름과 요구사항

| ID | 화면 | 우선순위 | 요구사항 및 완료 기준 | 상태 |
|---|---|---|---|---|
| R1 | STEP 1 내 상황 | P0 | 챗봇이 9가지를 하나씩 묻는다: 나이, 상황(직장인·학생 등), 회사·학교, 보증금(모아둔 돈), 월소득(세전), 출퇴근 허용 시간, 입주 시기, 집 유무, 세대 분리. 버튼 선택 또는 말하듯 입력("회사 다녀요" → 직장인, "1억 5천" → 15,000만 원, "한시간 반" → 90분). 넓은 지명은 다시 묻는다("강남" → 강남역·역삼역·선릉역·멀티캠퍼스 역삼 중 선택). "직", "ㅁㄴ", 한/영 오타는 넘어가지 않고 다시 묻는다. 끝나면 9개 답을 정리 카드로 보여주고, 카드를 누르면 그 질문만 다시 묻는다. 끝난 뒤 질문("35살인데 받을 수 있어요?")은 공고문 근거로 답하고 조건은 그대로 두며, 말로 알린 변화("월급 250으로 올랐어요")는 조건을 바꾼다. | 구현 |
| R2 | STEP 2 지원 추천 | P0 | 1단계 답으로 정책 자격·금액을 코드가 판정한다. 금액 계산 3개(국토부 청년월세, 서울시 청년월세, 중개보수·이사비) + 더 찾아본 지원 5개(안심계약 도움서비스, 청년안심주택, 전월세 대출보증, 임차보증금 이자지원, 주거공유). 결과는 총액("최대 520만 원")과 지금 신청 가능 / 내년 신청 지원으로 나눈다. 국토부·서울시 청년월세 중복 불가 시 금액이 큰 쪽을 자동 선택하고 이유를 보여준다. 조건별 충족·불충족·확인 필요와 근거 문장·출처, 시연일 기준 모집 상태(올해 접수 종료 여부, 내년 공고 알림)를 표시한다. 신청 시기와 함께 전입신고·세대 분리 할 일을 안내한다. | 구현 |
| R3 | STEP 2 조건 변경 재계산 | P0 | 1단계 조건 또는 "조건이 바뀌면?"(나이, 소득, 전세 계약)을 바꾸면 지원을 다시 계산한다. 예: 27세 520만 → 35세 280만, 41세·집 있음 → 지원 없음 + 이유, 월 420만 → 480만. | 구현 |
| R4 | STEP 2 공고문에 물어보기 (RAG) | P0 | 온통청년·정부24·주택도시기금·SH 공고문 약 1,200개 조각에서 TF-IDF로 찾아 답하고, 답 아래 근거 원문과 "원문 보기" 링크를 붙인다. 근거가 없으면 "찾지 못했어요" + 상담기관 안내. 만 19~39세 밖 질문은 AI 없이 복지로(129)·120으로 안내한다. 서버가 꺼져 있으면 미리 준비한 답으로 바꿔 화면이 깨지지 않는다. 평가: 공고문 원문과 대조한 22문항, 검색 22/22 · 근거 20/20 · 답 22/22 (LLM 연결 전 14/22). | 구현 |
| R5 | STEP 3 후보 집 넣기 | P0 | 후보 집 2~3곳의 주소와 보증금·월세·관리비를 직접 입력한다(카카오 주소·장소 검색). 주소 후보가 여러 개면 사용자가 고른다. 일부 조회가 실패해도 나머지 결과는 유지한다. | 구현 |
| R5-a | STEP 3 매물 정보 자동 입력 | P2 | 직방·다방 매물 캡처를 올리면 OCR로 글자를 뽑고, 매물 글을 복사해 붙여넣으면 OCR 없이 바로, LLM이 보증금·월세·관리비·면적·주소를 정리해 입력칸을 채운다. 코드가 단위·범위를 검사하고 못 찾은 칸은 비워 둔다(지어내지 않음). OCR은 표 배치를 잃어 항목과 숫자가 잘못 짝지어질 수 있으므로 사용자가 확인해야 비교에 들어간다. | 시간 남으면 |
| R6 | STEP 3 비교 | P0 | 출퇴근: ODsay 대중교통 시간·경로(없으면 거리로 추정), 1단계 허용 시간보다 길면 "○○분 넘음". 한 달 실부담: 월세 + 관리비(관리비를 모르면 "–"로 두고 더하지 않음). 보증금: 1단계 모아둔 돈보다 크면 "○○만 원 부족". 생활 시설: 마트·병원·편의점 등 걸어서 몇 분 + 누르면 동네 지도. 지도: 회사와 세 집 위치, 출퇴근 경로. 집별 지원: 집마다 ✓·✗·△와 이유, 최대 금액, "지원 받으면 한 달 실부담"(예: 신림 42만 → 22만, 월세 지원 20만 원 빼고). | 구현 |
| R7 | STEP 3 종합 추천 | P0 | 비용·시간·생활 0–100점 지표의 가중합. 프리셋 4개(균형 40/35/25 등) 선택, 또는 말로 한 우선순위를 AI가 가중치로 바꾸고 사용자가 화면에서 확인·조정한다. 종합 점수는 지원 전 금액 기준. "이렇게 추천했어요" 이유와 "아쉬운 점"을 표시하고, 미확인 지표는 화면에 표시한다. | 프리셋 구현 · AI 가중치 구현 예정 |
| R8 | AI 추천 보조 | P1 | 생활 점수 시설 고르기, 추천 이유 풀어 쓰기, "왜 신림이야?" 후속 질문 (3.4절). | 구현 예정 |
| R9 | 디지털 포용 (시각장애 청년) | P2 | 듣기 버튼, 큰 글씨·고대비, 말로 답하기, 음성 모드 (3.5절). | 시간 남으면 |
| R10 | 로그인 | P2 | 소셜 로그인 대신 **자체 사이트 로그인**(아이디·비밀번호 회원가입·로그인)으로 이름 표시. 시연은 이름 입력. | 시간 남으면 |
| R11 | 다음 단계 | P2 | 접근성 점검(axe-core), 장애인 청년 주거 지원 데이터, 서울시 전월세 실거래로 "예산에 맞는 동네" 추천, 실제 로그인·공고 알림, 정책 비교함·외부 캘린더. | 미구현 |

## 3. 화면·기능 상세

### 3.1 3단계 출퇴근 (구 4-4)

1. 1단계의 회사·학교를 공통 도착지로, 매물별 주소를 출발지로 쓴다.
2. 주소를 좌표로 바꾼 뒤 ODsay로 대중교통 시간·경로를 조회한다. 예: "멀티캠퍼스 역삼까지 지하철로 30분", "걸어서 13분".
3. ODsay 키가 없거나 조회에 실패하면 거리로 추정하고 추정임을 표시한다.
4. 1단계 출퇴근 허용 시간보다 길면 "○○분 넘음"을 표시한다.
5. 카카오모빌리티 자동차 길찾기는 쓰지 않는다. 청년 1인 가구는 대부분 대중교통으로 출퇴근하기 때문이다.
6. (추가 사항) 출퇴근 칸에 한 달 예상 교통비(ODsay 편도 요금 × 2 × 20일)를 참고로만 보여준다. 한 달 실부담과 비용 점수에는 넣지 않는다. 먼 집이 시간 점수에서 이미 깎이므로 비용에서 또 깎이지 않게 하고, 정기권·재택처럼 개인차가 큰 추정값이 비용 비교를 흔들지 않게 하기 위해서다.

### 3.2 종합 추천 계산 (균형 기준 비용 40% · 시간 35% · 생활 25%)

| 집 | 한 달 실부담 | 출퇴근 | 비용 | 시간 | 생활 | 종합 |
|---|---:|---:|---:|---:|---:|---:|
| 신림 | 42만 | 30분 | 100 | 70 | 87.5 | 86.4 |
| 성수 | 60만 | 30분 | 73 | 70 | 90 | 76.2 |
| 역삼 | 90만 | 13분 (도보) | 28 | 100 | 87.5 | 68.1 |

- 비용 점수는 가장 싼 집을 100점으로 두고 실부담이 1만 원 많을 때마다 1.5점 깎는다 (화면 숫자로 역산한 값이라 코드와 대조 필요).
- 집마다 지원이 달라지는 예: 27세면 세 집 모두 520만 원이지만, 역삼 집은 서울시 청년월세 조건을 넘는다(보증금 × 5% ÷ 12 + 월세 = 94.2만 원 > 93만 원). 35세가 되면 역삼만 40만 원으로 떨어진다.

### 3.3 AI와 데이터 원칙

**돈·자격·점수는 코드가 계산하고, AI는 사람의 말을 숫자로 옮기거나 코드 결과를 근거로 설명만 한다.**

검증 장치: 코드 판정(나이, 월세 조건, 신청 마감, 범위 밖), 숫자 검사(AI 답의 숫자가 근거에 없으면 원문 답으로 대체), 결론 검사(코드 판정과 반대 결론이면 코드 판정으로 대체), 출처 관리(출처 미확인 규칙은 근거에서 제외).

### 3.4 AI가 하는 일

| # | 자리 | AI가 하는 일 | 코드가 하는 일 | 상태 |
|---|---|---|---|---|
| 1 | 공고문에 물어보기 (RAG) | 공고문 근거로만 답 작성, 근거 원문 표시 | 검색·필터, 나이·월세·마감 판정, 숫자·결론 검사 | 구현 |
| 2 | 1단계 대화 이해 | "회사 다녀요", "한시간 반"을 조건으로 정리 | 값 검증, 못 알아들으면 다시 묻기 | 구현 |
| 3 | 말한 우선순위 → 가중치 | "회사 가까운 게 제일 중요하고 돈은 좀 더 써도 돼요" → 비용 25 · 시간 55 · 생활 20 | 점수 계산. 가중치는 화면에 보여주고 사용자가 확인·조정 | 구현 예정 |
| 4 | 생활 점수 시설 고르기 | "밤에 늦게 와요", "운동 꾸준히 해요" → 편의점·헬스장 포함 | 시설까지 거리·도보 시간 계산 | 구현 예정 |
| 5 | 추천 이유 풀어 쓰기 | 코드 계산값으로 자연스럽게 설명 | 숫자 검사 (근거에 없는 숫자면 틀 문장으로) | 구현 예정 |
| 6 | 매물 정보 자동 입력 | 매물 글(OCR로 뽑은 글 또는 붙여넣은 글)에서 보증금·월세·관리비·면적·주소 정리 | OCR, 단위·범위 검사, 못 찾은 칸 비우기, 사용자 확인 | 시간 남으면 |
| 7 | "왜 신림이야?" 후속 질문 | 계산된 비교 결과(실부담·출퇴근·생활·지원·점수 내역)를 넣어주면 그 값으로만 답 (검색 없음, RAG 아님) | 비교 결과 정리해서 넘기기, 숫자·결론 검사 | 구현 예정 |

음성 모드에서는 듣는 사람이 확인하기 어려워 추천 문장을 틀 문장으로 유지한다.

### 3.5 디지털 포용 (시각장애 청년) · 시간 남으면

| # | 기능 | 내용 | 난이도 |
|---|---|---|---|
| 1 | 듣기 버튼 | 1단계 질문, 2단계 결과, 공고문 답을 소리로 읽기 | 쉬움 |
| 2 | 큰 글씨·고대비 | 기존 "쉬운 화면"을 확장 (시각·저시력) | 쉬움 |

**음성 모드**
- 화면을 보지 않고 1~3단계를 말로 진행한다. 스크린리더와 겹치지 않게 자동 재생하지 않고 버튼으로 시작한다.
- 3단계 비교는 "결론 먼저 → 항목별 순위 → 차이 → 더 들을지 선택" 순서로 말한다. "돈", "성수랑 신림 비교", "역삼 자세히", "왜 신림이야?", "다시"로 이어간다.
- 음성 문장은 계산된 숫자로 코드가 틀에 맞춰 만든다. 화면과 음성의 숫자가 항상 같다.
- 마무리로 집 보러 갈 때 서울시 안심계약 도움서비스 동행을 안내한다.
- 기술: 크롬 Web Speech API(무료, 서버 불필요). 필요하면 클라우드 TTS·STT, 오프라인용 Whisper·MeloTTS로 확장.

## 4. 정책·비용 표시 기준

- 정책 판정과 금액 계산은 구조화한 조건과 코드로 처리한다.
- 정책은 조건별 충족·불충족·추가 확인 필요와 모집 상태를 표시한다. 자료에 없는 정보는 추가 확인 필요로 표시한다.
- 소득 기준: 2026년 1인 기준 중위소득 월 256.4만 원(보건복지부 고시). 세전 월급으로 추정하며 실제 심사는 서류로 한다.
- 서울시 청년월세 월세 조건은 코드로 계산한다: 보증금 × 5% ÷ 12 + 월세 ≤ 93만 원.
- **한 달 실부담 = 월세 + 관리비.** 관리비를 모르면 "–"로 두고 더하지 않는다. 보증금은 별도 표시한다.
- **종합 점수는 지원 전 금액**으로 계산하고, 지원 반영 실부담은 집별 지원 표에 따로 표시한다.
- 주거 전략(전세·월세 비교) 단계는 삭제했다. 사용자는 이미 후보 매물을 들고 오고, 실제 매물을 가져올 수 없어 전략 단계는 가상 금액뿐이며, 비용 비교는 3단계에서 실제 금액으로 한다.
- 차후 검토: 24개월 상세 시뮬레이션, 매물 함정 해석, 야간 안전 경로, 협상 연습.

## 7. 팀에서 정해야 할 것

1. **서버 구조.** 시연본은 Python(server.py, rag.py), 풀스택 계획은 Spring Boot. ① RAG·AI는 Python 서비스로 두고 Spring Boot가 호출 ② 전부 Spring Boot로 이전 ③ 시연은 현재 구조, 풀스택은 화면·데이터 저장만 담당.
2. **추천 점수 세부값.** 균형(40/35/25) 외 프리셋 3개의 가중치, 비용·시간 점수 감점 폭, AI가 낸 가중치의 허용 범위(합계 100, 각 0~100, 생활이 양수면 시설 1종 이상).
3. **지원 반영 실부담 계산법.** 지금은 월 지원액(월세 지원 20만 원)만 뺀다. 이사비 같은 1회성 지원과 기간이 다른 지원의 처리, 종합 점수 반영 여부.
4. **(추가 사항) 교통비 참고 표시.** 넣을지, 요금 × 2 × 20일 고정인지 1단계 상황(학생·직장인)에 따라 일수를 바꿀지.
5. **서비스 LLM 제공자·모델.** 정하면 22문항 평가 재실행.
6. **DB 범위.** 본선까지 5일이라 정책 버전 관리(DRAFT/PUBLISHED), revision 충돌 처리 같은 운영 수준 설계는 시연 이후로 미루고, 검증된 정책을 읽기 전용 시드로 넣는 방식이 현실적.
7. **담당.** AI 보조 자리(우선순위·시설·추천 이유·후속 질문) 담당. 시간 남으면 하는 기능(매물 자동 입력, 시각장애 강화안, 로그인) 담당.
8. **기능 확정 후** Figma 수정, 사용자 시나리오(페르소나) 작성.
