# my-house · 첫집 내비 (내 첫 집 파일)

처음 독립하는 청년이 **01 내 조건 → 02 받을 지원 → 03 집 고르기 → 04 할 일** 순서로 한 파일을 채워 가는 웹 서비스예요.
`~/Downloads/index/firsthome.html` 한 파일을 React(Vite) 프로젝트로 옮긴 거예요. 계산·판정·문구는 그대로이고, 화면만 컴포넌트로 나눴어요.

- PC 화면 전용이에요 (가로 1240px 이상).
- 처음 화면의 앱(폰) 그림을 **웹 브라우저 창 그림**으로 바꿨어요.
- 01 → 02로 넘어갈 때 **3초 로딩 화면**이 나와요.

## 실행

```bash
npm install
npm run dev        # http://127.0.0.1:5500
npm run build      # dist/ 에 배포용 파일
npm run preview    # 빌드한 결과 미리 보기
```

- 주소 끝에 `?easy=1`을 붙이면 처음 화면을 건너뛰고 **쉬운 화면**으로 시작해요. 예: `http://127.0.0.1:5500/?easy=1`
- Node 24.14에서 확인했어요. (Vite 8.3, React 19.2 · Vite 8은 Node 20.19 이상이 필요해요)

## 백엔드 함께 실행하기

프런트엔드는 `http://127.0.0.1:5500`, 백엔드는 `http://127.0.0.1:8000`을 사용해요.
5500이 이미 사용 중이면 프런트엔드는 오류로 종료하며 다른 포트로 이동하지 않아요.

다른 터미널에서 프로젝트의 Python 가상환경을 활성화한 뒤, `web/frontend` 폴더에서 `npm run dev:api`를 실행해요.
Windows에서는 프로젝트 루트에서 아래 명령으로 바로 실행할 수도 있어요:

```powershell
.\.venv\Scripts\python.exe scripts/server.py --port 8000
```

`web/frontend/.env`에는 `VITE_API_TARGET=http://127.0.0.1:8000`을 넣어 주세요.
`http://127.0.0.1:5500/api/health`에서 `"ok": true`가 나오면 프록시까지 연결된 상태예요.

## 환경 변수 (`.env`)

`.env.example`을 `.env`로 복사해서 채워요. 모두 비워 둬도 돌아가요.

| 이름 | 쓰는 곳 | 비워 두면 |
|---|---|---|
| `VITE_KAKAO_JS_KEY` | 카카오 지도 · 주소 검색 · 장소 검색 | 그림 지도(SVG)와 예시 집으로 보여줘요 |
| `VITE_ODSAY_KEY` | 대중교통 시간 · 요금 (ODsay) | 직선거리로 시간을 추정해요 |
| `VITE_API_TARGET` | `/api` 요청을 넘길 서버 주소 (예: `http://127.0.0.1:8000`) | 미리 넣어 둔 답으로 보여줘요 |

- 카카오 키는 카카오 개발자 콘솔에서 `http://127.0.0.1:5500`을 웹 플랫폼 도메인으로 등록해야 지도가 떠요.
- `VITE_`로 시작하는 값은 브라우저 코드에 그대로 들어가요. 서버 비밀 키는 넣지 마세요.

### `/api` 서버

화면이 부르는 주소예요. 개발 중에는 `vite.config.js`가 `VITE_API_TARGET`으로 넘겨줘요. 서버가 꺼져 있으면 화면은 미리 넣어 둔 답이나 후보 목록으로 바꿔서 보여줘요.

| 주소 | 하는 일 |
|---|---|
| `GET /api/health` | 서버가 켜졌는지 확인 (꺼져 있으면 AI 답 대신 준비된 답을 써요) |
| `POST /api/ask` | 02 공고문에 물어보기 · `{ question, profile }` |
| `POST /api/compare` | 03 이 비교에 물어보기 · `{ question, facts }` |
| `GET /api/place?q=` | 01 자주 가는 곳 검색 (카카오 키가 없을 때) |

서버 코드는 프로젝트 루트의 `scripts/server.py`예요. React 개발 시에는 위 명령으로 API를 8000에서 실행해요.

## 상태 관리 방식

- 원본처럼 앱 상태는 `store.js`의 객체 `S` 하나예요. `set({...})`으로 바꾸면 화면 전체를 다시 그려요 (`useSyncExternalStore`).
- `core.js`의 함수는 원본과 똑같이 `S`를 읽고 고쳐요. 그래서 판정 규칙을 바꿀 때는 `core.js`만 보면 돼요.
- 원본이 `getElementById`로 값을 읽던 입력칸(03 계약 조건, 주소 검색, 질문 칸)은 그대로 두려고 비제어 입력(`defaultValue`)으로 썼어요.
- 다 그린 뒤 할 일(포커스 옮기기, 버튼 그룹 Tab 자리, 카카오 지도 다시 그리기)은 `App.jsx`의 `useLayoutEffect` 한 곳에서 해요.

## 바뀐 점 (firsthome.html 대비)

1. **React 프로젝트**: 한 파일 → Vite + React. 기능은 그대로예요.
2. **웹 화면 그림**: 처음 화면 '스크롤 이야기'의 폰 그림을 600×440 브라우저 창으로 바꿨어요.
   - 창 위 막대(점 3개 · 자물쇠 · '내 첫 집 파일 / 0n 장 이름'), 왼쪽 목차 01~04, 본문, 오른쪽 도구 칸까지 실제 웹 화면 틀과 같아요.
   - 01은 +500만이 눌리며 금액이 쌓이고, 02는 금액이 올라가며 근거가 뜨고, 03은 순위 막대와 작은 지도, 04는 체크가 하나씩 켜져요.
3. **3초 로딩 화면**: 01에서 [받을 수 있는 지원 보기]나 목차의 02를 누르면 나와요.
   - 진행 막대가 0 → 100%로 차고, 나이 → 소득 → 무주택·세대 → 공고문 근거 순서로 내 값과 함께 체크돼요.
   - 3초 뒤 02 받을 지원으로 넘어가요. 탭이 뒤에 있어도 시간이 맞게 흘러요.
   - 화면 읽기 프로그램에는 지금 하는 단계를 읽어 줘요. 움직임 줄이기 설정이면 움직이는 효과를 빼요.

## 확인한 것 / 아직 안 한 것

- 01 입력 개편: 기본 정보 / 나의 예산 / 이사·이동 조건으로 나눴어요. 직업·학업 상태는 복수 선택, 기준 장소는 이름·주소 목록, 입주 시기는 연도·월 드롭다운과 '아직 미정'으로 골라요.
- 입주 시기는 `YYYY-MM`, 직업·학업 상태는 `prof.jobs`에 저장해요. 기존 `prof.job`과 상대적인 입주 시기도 읽고, 대학(원)생 선택은 지원 판정에 반영해요.
- 개편 후 확인: 빌드 성공, React 정적 렌더링, 복수 선택과 지원 판정, 날짜 선택·미정 전환, 장소 선택·변경, 9개 항목 완료 상태. 브라우저 연결이 없어 개편 화면의 시각 검수와 실제 클릭 검증은 아직 하지 못했어요.

- 확인함 (Chrome, 1440×900): 처음 화면 4장면, 01 입력 전부, 로딩 3초, 02~04 기능, 쉬운 화면 처음~끝, 콘솔 오류 없음, `npm run build` 성공.
- 아직 안 함: 실제 카카오·ODsay 키로 지도/교통, `/api` 서버가 켜진 상태의 AI 답, 가로 1240px 미만 화면.
